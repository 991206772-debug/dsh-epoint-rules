# Coder 通用红线

本文件是写代码时的判断依据，不是额外 Gate。命中的红线要落实到当前连续实现批次的代码、测试和计划验证中；未命中的实践不扩大需求。

1. 沿用项目已有 Epoint 后端、MiniUI/FUI 页面、DAO/Service/Action/Rest/Job 分层，不凭通用 Spring Boot、Vue、React、JPA、MyBatis 或 Lombok 经验替换项目范式。
2. 前端调用、后台 public 方法、参数、返回字段和页面回调必须真实闭合；不能写“后续补后台”或孤立 JS 函数。
3. 持久化字段、表、配置 key、队列名、菜单编码和已有 API 合同来自已确认 Design、真实项目或适用规则；新增业务方法、辅助类型可以按验收要求实现，不必先出现在骨架或方法清单中。技术实现缺口自行补齐，必要业务事实有冲突时不能猜。
4. 既有入口只做当前需求所需的最小增量，保留旧查询、保存、分页、按钮、URL 参数、id/class/bind/action 和资源引入；不顺手重构或格式化。
5. 多表、主从、批量、状态、外部调用和消息副作用要保持事务、幂等、失败处理或明确补偿；不能吞异常后返回成功。
6. 不把账号、密码、token、secret、证书、连接串和其它敏感配置写进代码、日志、测试数据或计划。
7. 需求闭环必须同时覆盖业务入口、后端逻辑、页面交互/接口、异常反馈和可执行验证；不能只生成页面、只留空方法或只声称骨架可用。
8. 普通字段必填、长度、格式提示沿用页面的 `required`、`requiredErrorText`、`maxLength`、`vtype`、`epoint.validate()`；ServiceInternal 处理权限、状态、跨字段关系、唯一性和流程前置条件，避免同一校验在多层重复。
9. 不修改规则/设计/状态真值文件，不调用 MCP/Gate 伪造阶段完成；实施计划只记录人读事实，代码完成以真实 diff 和验证命令为准。

开始每批实现前看当前命中的红线和实践；完成每批后只复查本批真实改动及其直接调用链。发现问题直接修复并重跑受影响验证，不开启没有失败证据的额外重构。
